Six Phases to Full Vision

Sci roadmap: from alpha to sovereign memory

The planned evolution of Sci from today's anonymization wedge through cross-provider memory consolidation, tracked across 103 strategy issues in Jira SCI.

The organizing thesis: The three pillars are a stack. Anonymity is the product. Memory is the retention. Sovereignty is the brand. This roadmap leads with the anonymization wedge — proving that reversible anonymization works reliably — and lets memory deepen only after that foundation hardens. Each phase builds confidence in the layer below it.

Phase 0: Land the Alpha in progress

Epic: SCI-261

Stabilize the core wedge. Merge PR #36 (proxy stability SCI-259/260 + embedder cold-start fixes), tag the alpha release, and run soak tests to verify the stability gates that make reversible anonymization trustworthy.

DoD: Merge & tag

Merge proxy stability PR (#36) with zero regressions. Cold-start latency under 1s. Tag v0.1.0-alpha release.

DoD: Soak gates

72-hour zero-crash soak test on proxy (Claude + GPT). Verify de-anonymization correctness end-to-end. Anonymity map consistency.

DoD: User triage

Collect feedback from early testers. Triage bugs vs. expected rough edges. Seed the roadmap with real use-case requests.

Phase 1: Extract the Wedge planned

Epics: SCI-271, SCI-272, SCI-273

Decouple sci-anonymizer from the main monorepo. Ship it as a permissively-licensed (MIT/Apache 2.0) standalone library with native bindings for JavaScript/WASM and Python/PyPI. Achieve cross-language feature parity and publish an honest benchmark against Microsoft Presidio — including the categories where Sci loses.

DoD: Repo extraction

Spin sci-anonymizer to its own GitHub repo. MIT license, contributing guidelines, README with usage examples.

DoD: Bindings parity

npm + WASM package (sci-anonymizer). Python package (sci-anonymizer-py). Both expose identical anonymization API. Full test suite cross-platform.

DoD: Benchmark

Honest comparison with Presidio on NER categories (PII, credit cards, phone). Show gaps: where Sci is stronger (session continuity) and where it loses (rare entity types). Publish with methodology.

Phase 2: MCP as Primary Distribution planned

Epics: SCI-297, SCI-298, SCI-299

Make Sci's MCP server the canonical way to deploy anonymization. One-command cross-platform install (macOS + Linux, Docker, Homebrew). Promote SQLite backend to tested default. Document the six MCP tools and publish an MCP anonymization-session convention that other tools can adopt.

DoD: Install story

brew install sci-mcp (macOS). apt-get install sci-mcp (Linux). Docker image with production hardening. Setup wizard for first run.

DoD: SQLite default

SQLite + pgvector as the tested, documented default storage. Upgrade migration from Postgres. Persistence verified across restarts.

DoD: MCP convention

Spec the six MCP tools (anonymize, de-anonymize, recall, store, status, export). Publish RFC for anonymization-session convention so other MCP tools can interop with Sci's identity map.

Phase 3: Multi-Provider Round-Trip planned

Epics: SCI-318, SCI-319, SCI-320

Extend the wedge to OpenAI, Google Gemini, and local models (Ollama). Implement streaming-safe de-anonymization (correct across SSE chunk boundaries). Harden the proxy and document an ADR on TLS-proxy vs. MCP-first distribution models.

DoD: Provider adapters

OpenAI, Gemini, and Ollama adapters with shared anonymization interface. Shared secret management. End-to-end tests with real LLM calls.

DoD: Streaming correctness

De-anonymization works correctly when responses arrive chunked. Token boundaries respected. No partial entity corruption in streaming flows.

DoD: Architecture decision

ADR on proxy vs. MCP distribution: when to use each, tradeoffs on auth/identity/observability. Harden proxy for production TLS load.

Phase 4: The Killer Demo planned

Epics: SCI-339, SCI-340

One identity, one local memory instance, seamlessly used with Claude, GPT, and a local model in a single session. All three providers see only pseudonymous tokens. Provider transcripts are verified pseudonymous (no identity leakage). Re-scope the macOS app as a UI over the MCP server. Consolidate sync to one adapter.

DoD: Cross-provider session

Single memory instance works with Claude, GPT, and Ollama in one workflow. Same pseudonym identity across all three. Provider logs show no real identity leakage.

DoD: Transcript verification

Export provider API call logs. Audit that de-anonymization map was never shared with providers. Demonstrate cryptographically that transcripts are pseudonymous.

DoD: macOS app refactor

Sci app becomes a UI shell over the MCP server (not a separate backend). One sync adapter for multi-provider memory. App shipping with live demo baked in.

Phase 5: Memory Consolidation v1 planned

Epics: SCI-353, SCI-354

Finish the memory layer: decay scheduling, episodic→semantic→identity promotion (no stub records), a recall-quality eval loop to measure retrieval accuracy. Gated strictly on real alpha-user feedback, not speculative design.

DoD: Decay + promotion

Episodic memory decays on schedule. Semantic promotion finished (no stubs). Identity facts permanent. Eval loop on retrieval precision.

DoD: User feedback loop

Instrument recall quality metrics. Gated on user complaints about missing context, not speculative improvements. Ship only what users asked for.

DoD: Portability story

Export memory across providers. Migrate from one Sci instance to another. Merge two memory graphs. Zero leakage of real identity in export.

Non-goals

  • Mem0 feature parity: We're not chasing advanced multi-agent memory patterns. Single-agent, single-identity recall is the current scope.
  • DID/Solid integration: Not committing to decentralized identity standards yet. Local-first and portable is enough for now.
  • Enterprise compliance: Not building with SOC 2, HIPAA, or GDPR as primary drivers. Privacy-first, but not compliance-first.
  • All sync adapters: We'll ship one high-quality adapter (likely Supabase or self-hosted sync). Not trying to support 10 backends.

Program success criteria (end of Month 6)

By end of Q2 2026, Sci roadmap is on track if:

  • External adoption: sci-anonymizer embedded by at least one external project (published with credit and link back).
  • Cross-provider demo: Tri-provider round-trip (Claude + GPT + local model) demo reproduced externally by an independent user.
  • Privacy audit: Zero privacy-guarantee violations reported. All identity leakage bugs fixed before users report them in production.
