System Design

Architecture

Monorepo spanning Rust core, TypeScript surface, and native distribution.

Overview

Sci is a polyglot system designed for sovereignty, correctness, and iteration speed. The Rust core handles security-critical operations (anonymization, embedding) with performance and portability guarantees. TypeScript packages layer on storage, MCP transport, and HTTP proxy. The macOS app wraps the system for end-user distribution.

Rust Core

~3,500 LoC across four crates. Portable, verifiable, compiled to WASM and native binaries.

TypeScript Surface

~10,000+ LoC. Storage adapters, MCP/HTTP servers, CLI, database layer, UI scaffolding.

Native Distribution

macOS app bundles the system as a desktop + system service with native system integration.

Core Crates (Rust)

Four production-focused crates in core/crates/:

Crate LoC Purpose Status
sci-anonymizer ~2,842 NER + regex + reversible token maps. Strips PII before LLM calls; reverses output. working
sci-embeddings ~695 ONNX Runtime running BGE-base-en-v1.5. Embeds messages for vector search. working
sci-oauth ~400 OAuth 2.0 + JWT token handling for secure API access. working
sci-handlers ~300 Request dispatching, context setup, error handling. working
Embedding Parity: Rust and TypeScript reference implementations verified at >0.999 cosine similarity. Reproducible across platforms.

Storage Backends

Pluggable storage layer supporting multiple databases and sync strategies:

Backend Vector Index Tested Status
PostgreSQL + pgvector HNSW (pgvector native) Yes, production working
SQLite + hnswlib hnswlib (via Node binding) Scaffolded, TS stubs partial
Cloud Sync — No; TS adapters only planned

Cloud sync targets (not yet implemented): Dropbox, S3, iCloud. Two-file model: `.db` (SQLite) and `.index` (HNSW binary), synced as atomic units.

Data Flow

User Message
↓
Proxy / MCP Server
↓
Anonymize (Rust sci-anonymizer)
↓
LLM Provider (sees tokens only)
↓
De-anonymize Response
↓
Embed (Rust sci-embeddings → pgvector)
↓
Store & Index in Memory

Each step is isolated. Rust handles crypto-sensitive operations; TypeScript handles orchestration and storage.

Database Schema

Located in db/init.sql (~250+ lines). Features:

  • Message and session tables with pgvector columns for embeddings
  • HNSW index configuration for semantic search
  • Audit tables for compliance and debugging
  • CHECK constraints for data integrity (no application-layer validation needed)
  • Migration scripts for schema versioning

Design Philosophy

Why This Stack?

  • Rust Core: Portability (compile to WASM, native, serverless), correctness (type system, memory safety), transparency (code auditable).
  • TypeScript Surface: Fast iteration on storage, protocol, and UI. Strong ecosystem for HTTP/MCP servers.
  • PostgreSQL: Proven vector search via pgvector + HNSW. Built-in audit, transactions, replication.
  • macOS App: End-user distribution with system integration (launch on login, system tray, local API).

Known Scaffolding

Several components are placeholders or incomplete:

  • Consolidator / Decay: Message consolidation logic is partial; decay scheduler not yet tested at scale.
  • Cloud Sync: Dropbox, S3, iCloud adapters are TS stubs. Model is designed; implementation pending.
  • Multi-provider: Extensible design for LLM providers; currently hardcoded to one provider per session.
  • SQLite Backend: Full integration deferred. Use PostgreSQL for production.
