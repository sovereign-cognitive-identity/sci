Memory Architecture

Three-Layer Storage

Sci's memory stack separates concerns for scalability and recall precision:

  • Episodic: Conversation turns, session context, raw exchanges. Short-lived, high-fidelity.
  • Semantic: Extracted facts, patterns, decisions. Indexed for dense/hybrid search. Medium lifespan.
  • Identity: Persistent user identity, preferences, values. Slow-moving, always accessible.

working All three layers operational. in progress Consolidation and promotion logic (decay + episodic→semantic→identity migration).

Integration & Control

MCP Server

Sci exposes a live Model Context Protocol server with six tools:

  • memory_recall — Query episodic, semantic, or identity memory with natural language.
  • memory_store — Persist facts, decisions, and context updates.
  • memory_identity — Load or refresh user identity (preferences, expertise, values).
  • memory_status — Inspect memory health, token usage, storage stats.
  • message_anonymize — Manually anonymize a message or snippet.
  • message_deanonymize — Restore PII in a de-anonymized response.

working All six tools ready for Claude Desktop and Claude Code integration.

Authentication & Permissions

Three auth tiers with granular read/write enforcement:

  • Trusted: Full read + write. Internal agents, same-device clients.
  • Standard: Read + selective write. External tools, verified origins.
  • Public: Read-only. Shared links, third-party integrations.

working Capability enforcement across all memory tiers.
