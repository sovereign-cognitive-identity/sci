Deep Dive: The Core Engine

Anonymization: reversible round-trip entity masking

Sci's differentiator is not destructive redaction — it's reversible anonymization. This page walks through how the hand-crafted Rust engine detects entities, substitutes tokens, and restores identity without ever exposing real data to the LLM provider.

The round-trip: from identity to tokens and back

Most privacy tools do one-way destructive redaction: you lose information forever. Sci does something rarer. Every piece of sensitive data goes through a four-step cycle:

Input (real data)
→
Detect
→
Tokenize
→
LLM sees tokens
LLM response
→
De-tokenize
→
Restored identity
→
You receive real data

The token map lives in-process only, held in memory as a Rust HashMap<String, String>. It is never persisted to any storage visible to the provider. This is the key: the session is the trust boundary. Within a session, the assistant knows who you are. Outside the session, the provider sees only stable tokens.

Detection: two paths to entity extraction

Sci identifies sensitive entities via two complementary detection mechanisms.

Path 1: Regex-based deterministic extraction

For entity types with well-defined structure, Sci uses hand-tuned regex patterns. These are fast, certain, and have zero false-negatives within their scope:

  • EMAIL: standard email pattern (user@domain.ext)
  • PHONE: US/international phone formats including +1, (xxx) xxx-xxxx, and variants
  • URL: http(s), ftp, and common schemes with domain and path extraction
  • HANDLE: social media handles (@username, #hashtags, Discord snowflakes)
  • API_SECRET: common API key patterns — AWS, OpenAI, Stripe, GitHub tokens, and private keys

These patterns are compile-time static and zero-copy. Each regex is tested against a corpus of real examples to avoid over-matching.

Path 2: Lexicon-based Named Entity Recognition (NER)

For less-structured entity types (PERSON, ORG, PLACE), Sci uses bundled lexicons:

  • ~500 common first names (US, UK, international) for PERSON detection
  • US states and territories for PLACE recognition
  • Bundled geographic and organizational lexicons loaded at startup
  • Compound-entity detection: sequences like "John Smith" or "Apple Inc." are recognized as single entities, not split across tokens
  • Allowlist filtering: entities tagged with high certainty are promoted to identity_facts after 3+ occurrences in a session — strengthening recall and mitigating lexicon gaps for repeated names

Reversibility: the session token map

Each session maintains a single source of truth: a HashMap<String, String> that maps entity → token. This map is:

  • Session-scoped: created fresh at session start, destroyed at session close
  • In-process only: never serialized, never uploaded, never stored in a database visible to the provider
  • Deterministic: the same entity always maps to the same token (PERSON_1 is always PERSON_1 within the session)
  • Queryable: deanonymize() walks the response token-by-token and restores the real data using the same map

This design has a profound implication: you never lose context. The LLM learns about your situation, your relationships, your problems — but always through a pseudonymous lens. On the receiving end, you get the LLM's response with your real identity restored.

Session start: token_map = {}

Input: "Casey emailed support@example.com about the outage."

Detect: [PERSON: "Casey", EMAIL: "support@example.com"]

Tokenize:
  token_map["Casey"] = "PERSON_1"
  token_map["support@example.com"] = "EMAIL_1"

Output to LLM: "PERSON_1 emailed EMAIL_1 about the outage."

---

LLM responds: "PERSON_1 should check with EMAIL_1 immediately."

Deanonymize:
  token_map["PERSON_1"] = "Casey" ✓
  token_map["EMAIL_1"] = "support@example.com" ✓

Output to you: "Casey should check with support@example.com immediately."

Cascade feedback: learning from repetition

A session feedback mechanism strengthens entity recognition over time. If an entity appears 3+ times within a session, it is promoted to identity_facts — a higher-confidence store that informs future sessions and mitigates lexicon gaps for names that appear repeatedly.

Example:

  • First mention: "Sarah" detected via lexicon, tagged PERSON_1
  • Second mention: "Sarah" re-detected, re-mapped to PERSON_1 (deterministic)
  • Third mention: "Sarah" promoted to identity_fact — will be recognized with higher confidence in future sessions

Recent fixes (SCI-259, SCI-260) addressed proxy crashes and false-positive cascades when handling repeated entities in high-volume conversations. The engine now gracefully deduplicates cascade feedback and avoids re-promotion of already-promoted entities.

Honest limitation: lexicon gaps and proper nouns

The NER is lexicon-based, not neural. This means Sci can miss single-capital proper nouns that aren't in its bundled lexicons. A name like "Xandra" or a company like "Databricks" may not be recognized on first mention if it doesn't match a regex or appear in the name lexicon.

The cascade-feedback design partly mitigates this: once the name appears in the second prompt of a session, it will be recognized and promoted to identity_facts for future reference. But there is a real ceiling: a one-shot mention of an obscure proper noun has a real risk of leakage.

The planned evolution: hybrid on-device transformer NER (e.g. small distilled BERT or similar) to catch proper nouns with higher recall, while keeping the lexicon path as a fast fallback. This is on the roadmap.

Scale and testing

Codebase: ~2,842 lines of hand-crafted Rust across the sci-anonymizer crate, covering entity detection, token mapping, session lifecycle, and the cascade-feedback system.

Coverage:

  • 17 integration tests covering real-world text anonymization end-to-end
  • 3 parity tests validating Rust implementation against the TypeScript reference implementation
  • Documented edge cases (SCI-195, SCI-196, SCI-197) including compound entities, single-cap proper nouns, and cascading feedback deduplication

Benchmarking: Sci publishes honest benchmarks against Microsoft Presidio rather than hiding the ceiling. The lexicon approach is deterministic and fast for structured types (EMAIL, PHONE, URL) but trades recall for precision on proper nouns. This is intentional — false negatives in proper noun detection are addressable via cascade; false positives in regex detection are critical failures.

Connections to the broader system

Anonymization is the wedge. It exists to serve the two higher layers of the stack:

  • Memory: The anonymized tokens are what get embedded and stored. Sci's memory system uses the same token map to retrieve pseudonymous context without ever materializing real identity to the embedding provider.
  • Sovereignty: The token map is held locally. No cloud service, no external NER API, no reliance on a third-party privacy vendor. The guarantee is auditable because the evidence is on your hardware.
