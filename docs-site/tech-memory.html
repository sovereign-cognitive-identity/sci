Technical Deep Dive

Memory & Embeddings

Three-layer memory model with sovereign, local embeddings and hybrid retrieval.

The Three Memory Layers

Sci structures memory as three distinct layers, each optimized for different recall patterns and time horizons:

Layer What It Stores Status
Episodic Raw events, messages, sessions, and raw interactions — the full event log with timestamps and context. Implemented
Semantic Distilled facts, patterns, and insights extracted from episodes — abstracted knowledge without timestamp noise. Partial
Identity Durable facts about the person: preferences, values, expertise, relationships, ongoing decisions. Implemented

Each layer is queryable by dense embedding + optional full-text search. The consolidation pipeline (episodic → semantic → identity promotion) is stubbed and deferred; see below.

Embeddings: Sovereignty by Default

Sci embeds text using BAAI/bge-base-en-v1.5, a 768-dimensional BERT encoder. Critically: embeddings are computed locally via ONNX Runtime in the sci-embeddings crate (~695 LoC), not sent to a cloud provider.

This design choice is deliberate:

  • Sovereignty. No per-query data exposure. Text never leaves the machine.
  • Parity. Rust and TypeScript implementations achieve >0.999 cosine similarity, verified by integration tests.
  • No vendor lock-in. Swap embedding models locally; the system doesn't depend on Voyage AI, OpenAI, or other APIs.
Performance note: ONNX graph optimization is set to Level 1, not Level 3. Level 3's extended graph rewrites took 10–15 minutes on cold start for BGE-base and triggered macOS Jetsam kills in restart loops. Level 1 starts in milliseconds and achieves equivalent inference speed for a simple BERT encoder.

Storage & Retrieval: Hybrid Search

Sci stores embeddings and text in PostgreSQL + pgvector with an HNSW index. At query time, retrieval is hybrid:

Text input
→
Embed (BGE/ONNX, 768-d)
→
Store (pgvector + tsvector)
Query text
→
Dense vector search (pgvector cosine)
→
Full-text search (tsvector / plainto_tsquery)
→
RRF merge (k=60)
→
Ranked results

Why hybrid beats pure-vector: Dense embeddings excel at semantic similarity but fail on exact lexical matches (e.g., searching for a specific tool name or date). Full-text search is the inverse — precise for keyword queries but insensitive to synonymy. Hybrid search via Reciprocal Rank Fusion merges both signals, giving users the best of both worlds: semantic recall for open-ended queries plus exact matches where needed.

The retrieval backend lives in packages/core/src/storage/local-adapter.ts.

Embeddings Crate: ~695 Lines

The sci-embeddings crate implements ONNX Runtime inference for BGE-base-en-v1.5. Key responsibilities:

  • Load the BERT model and tokenizer.
  • Encode text to 768-dimensional vectors.
  • Normalize outputs for cosine similarity.
  • Maintain embedding parity with TypeScript implementations (>0.999 cosine).

The crate is intentionally minimal — it does one thing well. Graph optimization, tokenization, and normalization are all standard ONNX practices; the code is straightforward and testable.

Consolidation: Known Gap (Deferred)

Consolidation is incomplete. The episodic→semantic→identity promotion pipeline is stubbed. Decay and consolidation logic exist in decay.ts (~72 LoC, partial) and consolidator.ts (~100 LoC, stubbed), but are not production-ready.

This is intentional. Consolidation — deciding which episodic facts bubble up to semantic knowledge, and which become identity beliefs — is the most opinionated part of the system. It requires user feedback to tune: which memories resurface often? Which fade too quickly? Which feel permanent?

The decision: defer consolidation until the anonymization wedge has real users. Then, driven by observed recall complaints and usage patterns, build the promotion rules that matter. Premature consolidation logic is technical debt; observed consolidation is gold.

Fallback: SQLite + hnswlib

For single-machine deployment (no Postgres), Sci has planned stubs for SQLite + hnswlib (lightweight HNSW). This is not yet integrated. When needed, the swap is mechanical: implement the same StorageAdapter interface, swap the backend, and the rest of the system remains unchanged.

Testing & Verification

  • Retrieval integration tests confirm that hybrid search returns expected memories in expected order.
  • Embedding parity tests verify Rust vs TypeScript implementations achieve >0.999 cosine similarity across a corpus.
  • Performance tests track embedding latency and graph optimization impact.
