Overview

MCP Server

The MCP (Model Context Protocol) server is the strategic distribution surface — the best integration point for agents, developers, and multi-model AI workflows.

What it is

A stdio-based MCP server that exposes six core tools:

Tool Purpose Tier
memory_recall Query stored memories by topic or agent session read
memory_store Persist a memory with optional tagging and source write
memory_identity Load identity context (preferences, projects, expertise) read
memory_status Inspect server health and memory stats read
message_anonymize Strip PII from a text payload read
message_deanonymize Restore previously anonymized text read

Integration example

Register the MCP server in Claude Desktop or Code:

npx @sci/mcp add

Or manually in claude.config.json:

{
  "mcpServers": {
    "sci": {
      "command": "npx",
      "args": ["@sci/mcp"],
      "env": {
        "SCI_HOME": "~/.sci"
      }
    }
  }
}

Auth tiers

The MCP server enforces three capability tiers (configured per client):

  • Trusted — read and write to identity, memories, and message operations
  • Standard — read and write to memories only; identity is read-only
  • Public — read-only to memories; no identity or message ops

HTTP Proxy

A Hono-based HTTP server (port :3001) that terminates TLS and anonymizes outbound traffic. Useful when Sci acts as a gateway for Claude API calls, stripping headers and session state before forwarding.

Why this exists

In early Sci deployments, the proxy provided a single point for anonymization and rate limiting. It remains useful for certain deployment topologies.

Operational cost

TLS termination is a maintenance tax. Recent work (SCI-259, SCI-260) stabilized crash-on-reconnect and false-positive cascade behavior, but the proxy remains operationally heavier than the MCP server.

working (after stability fixes)

CLI

Direct command-line access to memory operations, useful for scripts and local development.

sci recall "recent decisions about embeddings"
sci store "Chose BGE-base-en-v1.5 over Voyage. Reason: sovereignty."
sci identity
sci status

macOS app

Alpha consumer-facing UI for onboarding, identity inspection, and session status. Currently being re-scoped: rather than a parallel, independent implementation, it will layer over the MCP server, reducing code duplication and maintenance burden.

alpha / re-scoping

Strategic direction

MCP is the primary surface

The agent ecosystem is consolidating around MCP. Sci's future is MCP-native:

  • Cross-platform (macOS, Linux, Windows via Node.js)
  • Lower maintenance burden than a proxy
  • Aligns with how developers integrate AI tooling today
  • Single distribution channel for CLI, agents, and consumer apps

Next step: One-command install via npx, Homebrew, and Docker. Today, distribution is via alpha tarballs.
