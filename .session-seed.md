# Session seed — 2026-05-07 (web → desktop handoff)

Paste these as separate `memory_store` calls on your Mac, or just hand this file
to the next Claude Code session.

## What happened

- Casey's local Claude Code CLI and Claude Desktop on MBP were broken: errors
  `ConnectionRefused` and `undefined is not an object (evaluating '_.input_tokens')`.
- Root cause: `~/.zshrc` sets `ANTHROPIC_BASE_URL=http://localhost:3001`, which
  routes Claude Code through the local sci proxy (`com.sci.proxy` LaunchAgent).
  The proxy was down, so the CLI got connection refused. The Desktop symptom was
  unrelated — a WireGuard tunnel that was up and blackholing traffic; Casey
  killed the tunnel and Desktop recovered.
- Workaround that unblocked the CLI: `ANTHROPIC_BASE_URL=https://api.anthropic.com claude`.
- Reference doc with full context: `PROXY_RESEARCH.md` at repo root (recovery
  procedure section in particular).

## Open architectural question (the real topic)

Casey asked: do we still need the **local** proxy now that traffic egresses via
WireGuard → VPS gateway?

Answer given: VPN ≠ proxy. VPN handles network-layer sovereignty (egress IP,
traffic shape). The sci proxy does two things VPN does not:
1. **Anonymizes prompt content** before it leaves the machine.
2. **Injects sci memory context** into outbound requests.

## Recommendation on the table (not yet decided)

Move the proxy off the laptop and run a single instance on the VPS gateway.
Every device on the WireGuard net points at it:

```
ANTHROPIC_BASE_URL=http://<vps-tunnel-ip>:3001
```

Tradeoff: VPS now sees decrypted prompt content, so it must be trusted at the
same level as the laptop. Casey controls the VPS, so probably acceptable —
needs explicit confirmation before implementing.

Alternative: drop the proxy entirely if anonymization + memory injection are no
longer wanted. Disable steps are in `PROXY_RESEARCH.md` "Recovery Procedure".

## Next action when picking this up

Decide between:
- (a) Migrate proxy to VPS — needs: deploy plan, new ANTHROPIC_BASE_URL on each
  client, decommission local LaunchAgent, verify memory injection still works
  end-to-end.
- (b) Keep local proxy — just restart it (`launchctl kickstart -k gui/$(id -u)/com.sci.proxy`)
  and investigate why it crashed (logs at `~/Vault/sci/proxy.log`).
- (c) Disable proxy entirely — sed block in `PROXY_RESEARCH.md`.
