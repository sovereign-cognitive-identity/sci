Where Sci Should Go

An opinionated strategy synthesis — codebase audit + competitive landscape, June 2026
The one-sentence verdict: Sci's defensible, rare asset is reversible anonymization for LLM round-trips — nobody else in OSS or commercial does it well — and the project should reorganize around that wedge, distribute it through the MCP/agent ecosystem, and let memory and sovereignty be what the wedge unlocks rather than three co-equal pillars fighting crowded markets.

1 · Honest audit: what Sci actually is today

PillarStateReality check
AnonymityStrongest 2.8k LoC Rust anonymizer, regex + lexicon NER, session-scoped reversible token maps, real tests, documented edge cases (SCI-195/196/197), proxy works end-to-end for Claude. Genuinely production-track.
MemoryWorks, but mid-pack Hybrid retrieval (pgvector + tsvector + RRF), local BGE embeddings via ONNX — solid. But consolidation/decay/promotion are stubs, and this exact feature set is what Mem0/Letta/Zep ship with far more ecosystem traction.
SovereigntyReal principle, fuzzy product Local-first is genuine (no cloud creds, on-device embeddings). But sync adapters are stubs, multi-provider (OpenAI/Google) is stubbed, distribution is macOS-only. "Sovereignty" today = an architectural stance, not a feature a user can point at.

Sources: full codebase audit (sci-anonymizer, sci-embeddings, packages/core, packages/proxy, @sci/mcp); maturity = credible alpha, beta candidate.

2 · The landscape, compressed

Memory: crowded, VC-funded Mem0 (~8.5k★, Series A) owns cloud agent memory. Letta, Zep/Graphiti, Cognee fill the rest. Competing here head-on as "another memory layer" is a losing fight for a solo OSS project.
PII redaction: crowded, but one-way Presidio (~12.5k★), LLM Guard, Private AI, gateway guardrails (Portkey, Kong, Cloudflare) all do destructive redaction. None restore identities in the response. The round-trip is unowned.
Sovereignty/SSI: weak tailwind Solid/DIDs remain niche with zero LLM-provider integration. "Sovereign AI" as a *trend* is real (EU AI Act enforcement, GDPR pressure, on-device inference) — but the SSI *standards stack* is not where the energy is. Don't build on it yet.

⚠️ Researcher market-size figures (€200–500M etc.) are soft estimates — treat the direction (reversible anonymization unowned, memory crowded, regulatory tailwind real) as the finding, not the numbers.

3 · The strategic insight

Sci's three pillars aren't peers — they're a stack. Anonymization is the wedge (rare, working, defensible). Memory is the retention layer (what makes the wedge sticky — your assistant still knows you even though the provider doesn't). Sovereignty is the brand (the why, not a feature list).

The mistake to avoid: marketing Sci as a memory product. The moment you say "memory layer," you're compared to Mem0 and you lose on stars, integrations, and funding. The moment you say "use any LLM without it ever seeing who you are — and keep your own memory on your own machine" — nobody else is in that sentence.

4 · Recommended direction

Positioning

"The privacy layer between you and every AI."
Sci is the local-first proxy + memory that anonymizes everything outbound, de-anonymizes everything inbound, and keeps the only copy of who-you-are on hardware you control. Memory portability across providers falls out of the architecture: Claude, GPT, and local models all see the same pseudonymous you and share the same local memory.

Three moves, in order

  1. Extract sci-anonymizer as a standalone, embeddable OSS component. Rust crate + WASM/npm binding + Python binding. "Reversible Presidio for LLM round-trips." This is the influence play: a thing other projects (LiteLLM, Open WebUI, MCP servers, agent frameworks) can embed earns stars, contributors, and standard-setting power in a way a monolithic app never will. License it permissively; the integrated Sci product stays the flagship.
  2. Make the MCP server the primary distribution surface, not the macOS app. MCP is where the agent ecosystem is consolidating. memory_recall/store/identity + message_anonymize/deanonymize already exist and work. Ship it as a one-command install (npx / Homebrew / Docker), cross-platform. The macOS app becomes the consumer-friendly skin later, not the gate.
  3. Finish the round-trip story across providers before deepening memory. OpenAI/Google proxy support is currently stubbed — that's the gap between the positioning ("every AI") and the product (Claude-only). Close it before investing in consolidation/decay/graph memory. A working tri-provider reversible proxy is a launchable, demoable, blog-postable artifact; smarter memory decay is not.

What to deliberately NOT do

  • Don't chase Mem0. No graph memory, no consolidation research, no "memory benchmark" arms race until the privacy wedge has adoption.
  • Don't build on DIDs/Solid now. Watch it; integrate in 2027+ if providers ever adopt. Today it's effort with no users on the other end.
  • Don't go enterprise-compliance-first. The GDPR/AI-Act tailwind is real, but a solo OSS project can't run an enterprise sales motion. Let the compliance story pull enterprises toward you (docs, audit-trail design, PRIVACY.md rigor) rather than building SOC2-shaped features speculatively.
  • Don't finish all the sync adapters. Pick one (probably iCloud for the mac story or plain file-based) and delete the rest until someone asks.

What makes it influential (not just used)

  • Own a term: "reversible anonymization for LLMs" / the anonymize→infer→de-anonymize round-trip. Write the definitive technical post; publish the edge-case test corpus (SCI-195/196/197 work is genuinely interesting content).
  • Propose the pattern as an MCP convention — a lightweight spec for anonymization-session tools. Reference implementations beat manifestos; you already have one.
  • Publish honest benchmarks: entity-recall/precision of the Rust NER vs Presidio on a public PII corpus, plus round-trip fidelity. Honest numbers (including losses) build more credibility than claims.

6 · Risks worth naming

RiskRead
Providers ship native privacy modes (zero-retention, on-device)Real but partial — provider promises are contractual; Sci's is architectural ("they never had the data"). That distinction is the moat; keep it sharp in messaging.
Lexicon NER quality ceilingThe honest weakness. A small on-device transformer NER (or hybrid) is likely needed within a year; the cascade-feedback design already mitigates. Benchmark publicly and own the limitation.
Solo-maintainer bandwidthThe extraction strategy is also the mitigation: a small embeddable crate attracts contributors far more easily than a monorepo app.
Proxy fragility (SCI-259/260 class bugs)TLS-terminating proxies are an operational tax forever. The MCP-tool path (anonymize/deanonymize as explicit tools) is the lower-maintenance surface — lean distribution toward it.
Bottom line: You set out to build Anonymity, Memory, and Sovereignty. The market just told you the order: Anonymity is the product, Memory is the retention, Sovereignty is the brand. Extract the anonymizer, ride MCP for distribution, make the round-trip work everywhere, and name the category before someone bigger notices it's empty.
